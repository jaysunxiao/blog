# godot-framework 开源了：给 AI 时代的 Godot 项目一个底座

用 AI 写游戏，确实爽。一个晚上原型就能跑起来，门槛低得吓人。

但这个爽有边界。AI 擅长局部——补个函数、填段脚本、修个小 bug。整座工程它扛不住。偏偏很多人反过来干：把整个仓库扔给 AI，靠「下一句提示词」往前推。没架构，没边界，堆着堆着就成屎山了。跑起来不难，一动结构，半个仓库一起炸。

说白了：AI 负责创造，人类负责还债。

纯靠提示词堆出来的东西，演示没问题，上线是另一回事。想跳出这个坑，顺序得反过来——**底座交给框架，AI 只填局部**。

所以我做了 [godot-framework](https://github.com/godot-fun/godot-framework)。MIT 开源。

它不是又一个「上帝引擎」。它是三层叠在一起的东西：

1. **运行时底座**（`zfoo/`）：拷进工程就能用的 Godot 能力
2. **Harness Rules**：目录怎么分、脚本怎么写、改动怎么克制，写进仓库，agent 跟着走
3. **Agent Skills**：图片 / 音频 / 视频从生成到入库的处理流水线

下面分开说。

---

## 三分钟接入

1. 把 `zfoo/` 拷进你的 Godot 工程
2. 项目设置 → Autoload，注册：

| Name | Path |
|------|------|
| `GodotFramework` | `res://zfoo/GodotFramework.tscn` |

3. 开玩

框架代码和游戏业务分开。升级框架时同步 `zfoo/` 即可，别往里面塞玩法逻辑。

## 运行时里有什么

### AI 对话（OpenAI 兼容）

环境变量设 `OPENAI_API_KEY`，或者直接改 `OpenAiClient` 的 `api_key` / `base_url` / `model`：

```gdscript
var reply := await OpenAiClient.async_chat("hello", "you are a helpful assistant")

var messages: Array[ChatMessage] = []
messages.append(ChatMessage.new(ChatMessage.ROLE_USER, "hello"))
var reply2 := await OpenAiClient.async_chat_messages(messages)
```

几行就能把对话接到游戏流程里。AI 是打下手，不是反客为主。

### 玩家摸得到的手感

音乐淡入淡出、多通道音效、浮动提示、精灵表特效，开箱就有：

```gdscript
Audio.play_music("res://audio/bgm.mp3")
Audio.play_musics(["res://audio/a.mp3", "res://audio/b.mp3"])
await Audio.play_voice("res://audio/narration.mp3")
Audios.play("res://audio/click.mp3", 0.8)

Alert.alert("Saved successfully", Colors.success)

EffectAnimation2D.spawn(Vector2(500, 200), self, "res://effects/attack.png", Vector2i(4, 4), 0.5, 13)
```

### 主线程别拖垮

异步加载、场景切换、定时任务：

```gdscript
var texture: Texture2D = await ResourceHelper.async_load("res://assets/icon.svg")
await SceneHelper.async_change_scene_to_file("res://scene/Main.tscn")
SchedulerBus.schedule(func() -> void: do_something(), 1000)
SchedulerBus.schedule_at_fixed_rate(func() -> void: poll_status(), 2000)
```

### 联网走路由

TCP / WebSocket / HTTP 都有。发包、收包、请求应答，统一走 `Router`，别让 AI 在每个脚本里各糊一套：

```gdscript
var session: Session = TcpClient.new(Codec.new(), "127.0.0.1:80")
Router.register_receiver(LoginResponse, func(packet: LoginResponse) -> void: on_login_response(packet))
Router.send(session, SomeRequest.new())
var reply: LoginResponse = await Router.async_ask(session, LoginRequest.new())
```

### 出事了能查回来

日志落盘到 `{user_data}/logs/godot.log`：

```gdscript
Log.info("player login uid:[{}]", user_id)
Log.error("load failed path:[{}] err:[{}]", path, err)
```

### 上线后还能改

单 PCK 热更新：启动 → 查版本 → 下载 PCK → MD5 校验 → 加载 → 进游戏。玩具和产品的差距，经常就卡在这一步。

### 改完心里有底

挂上 `UnitTest`：扫描同目录 `.gd`，方法名以 `test` 开头或结尾就当测试跑。`assert` / `Log.error` / `printerr` 失败即 fail-fast。

挂上 `IntegrationTest`：同目录名字带 `test` 的场景一个个实例化，场景跑完发 `test_passed` 再进下一个。

零插件，不绑编辑器面板。你用 Cursor / Claude 写代码时，很少打开 Godot 也没关系。

### 日常零活

字符串、时间、JSON、文件、配置、主线程回调、优雅退出——不用每个项目现写一遍：

```gdscript
var obj = JsonUtils.json_to_object('{"name":"test","age":10}', Student)
var json := JsonUtils.object_to_json(obj)

Setting.set_bool("sound_enabled", true)
Setting.save()

gdf.callable_deferred(func() -> void: refresh_ui())
await gdf.quit()
```

## 规则：别让 agent 把骨架写散

光有 API 不够。AI 写 Godot 时，可抄的规范本来就少，一不小心就把资源和脚本搅在一起。

仓库里的 `.cursor/rules/` 把这些钉死了，比如：

- `zfoo/` 只放框架，别塞业务
- `image/` / `audio/` / `assets/` 按类型放资源，里面不写 `.gd`
- 游戏逻辑在 `scene/` 和 `script/`
- 改动要克制：别顺手「优化」旁边没坏的代码

Cursor、OpenCode 原生支持。Codex / Claude 把 rules 和 skills 拷到对应目录即可（README 里有表）。

agent 有车道可跑，比每次口头叮嘱靠谱。

---

## Skills：素材一条龙

游戏做完还要出片、出资源。`.cursor/skills/` 里是一批批处理脚本，按流水线跑，默认不覆盖源文件。

大致分类：

| 类别 | 在干什么 |
|------|----------|
| Audio | 转 WAV → 去静音 → 降噪 → 淡入淡出 → 响度 → 采样率 → OGG |
| Image | 转 PNG → 去水印 → 切精灵表 → 抠图 → 裁边 → 缩放 |
| Video | 去水印 → 抽/静音 → 升 4K → 合并 → OGV |
| Storyboard | 分镜 → 双语配音 → 和视频合成 → 成片 |
| AI | 音色克隆 TTS（IndexTTS2） |

分镜、配音、成片这条链，我自己也在用。不是 PPT 里的「未来规划」。

## 适合谁

- 用 Godot 做独立游戏，想要一层薄薄的公共底座，而不是从零拼 Log / 网络 / 热更
- 已经在用 AI 写代码，但受够了「能跑、不敢改」
- 希望目录和写法有约束，agent 别把工程写散

不适合的情况也很清楚：你只想做一个周末 demo，或者你已经有成熟自研框架——那没必要换。
