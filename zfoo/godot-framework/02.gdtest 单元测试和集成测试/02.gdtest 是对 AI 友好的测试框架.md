# Storyboard — gdtest：对 AI 友好的 Godot 测试框架

## Materials
- 旁白全文（约 2 分半～3 分钟）→ 叙事与事实来源
- 对比对象：GUT（广为人知的完整测试插件，编辑器面板跑测）→ 对照，不夸大其短处
- 产品：`gdtest`，`godot-framework` 自带；路径 `zfoo/gdtest`
- 卖点（材料内）：零插件；0 API（Godot 原生 `assert`）；约一两百行；AI 友好、无复杂约定继承
- 单元测试：`UnitTest` 挂场景 → 扫描同目录 GDScript → 方法名以 `test` 开头或结尾 → `assert` / `Log.error` / `printerr` 失败且 fail-fast
- 集成测试：`IntegrationTest` → 同目录名含 `test` 的场景依次实例化 → 场景约定发 `test_passed` 再进下一个
- 收束理念：够用、好懂、可直接进项目；CTA：打开 `zfoo/gdtest`，挂场景，写第一条 `*_test`
- 工具语境：Cursor / Opencode / Claude；AI 时代较少打开 Godot 编辑器

## Visual Style
- Medium: 技术解说片 + 屏幕录制感（代码编辑器 / 文件树 / 极简 Godot 场景树示意），偶有扁平图标化 UI，非游戏过场 CG
- Mood: 冷静、利落、略带「翻盘」感——从重插件习惯切到轻量方案
- Color / light: 深色 IDE（炭灰底、青绿/琥珀高亮语法）；对比镜头略偏暖橙（「旧习惯」）vs 冷青（「gdtest」）；干净负空间
- Camera: 固定为主，轻推/轻移跟随光标与文件高亮；列表优势用节奏分明的切镜或侧滑卡片
- Motion energy: 中低——光标点选、文件扫描动效、断言打勾/打叉、场景依次加载；避免炫技粒子
- Aspect: 16:9

## Spine
冷开场先甩「装 GUT、编辑器面板跑测」的熟悉动作 → 立刻反转「AI 工具里几乎不开 Godot」→ 急需轻量 AI 友好方案并点名 `gdtest`（godot-framework / `zfoo/gdtest`）→ 相对 GUT 的四条优势各一镜 → 单元测试三步（挂载扫描 / 命名约定 / fail-fast）→ 集成测试两步（排队实例化 / `test_passed`）→ 理念收束 + CTA。全片约 2 分半～3 分钟；单镜目标约 **10 秒**。Shot 01 只抓注意力，不提前讲完产品。
